# Jazzytory — 마스터 프롬프트 (윤문본 v1.0)

> 원 요청을 제품 스펙 수준으로 다시 쓴 문서. 모든 에이전트는 작업 전 이 문서를 읽고,
> 자신의 산출물이 여기 정의된 **성공 조건**을 만족하는지 확인한다.

---

## 0. 원 요청 (Raw)

> "재즈피아노 연주 전공 대학 커리큘럼을 그대로 반영하고 버클리음대 등 유수의 재즈피아노
> 연주 전공 교수들의 검수까지를 포함하여, 사용자들이 이 서비스를 사용해서 체르니 100수준의
> 사용자가 리얼북 악보만을 보고 세련된 즉흥 재즈 연주가 가능하도록 하는 웹 서비스를 만들어봐.
> 완성도 있는 웹 서비스 개발 프로세스와 같이 각 프로세스 기능들을 담당할 에이전트를 만들고,
> 이 프롬프트를 다시 한 번 윤문하여 그 프롬프트를 완성한 후에 에이전트들을 만들고 실제 웹
> 서비스를 구현해봐. 재즈피아노 연주 교육 시스템, 필수 청음 명반 리스트, 이미 오픈된 유튜브의
> 적절한 강의들을 임베딩 해주거나 뭐 그런 아이디어들을 포함하는거지."

---

## 1. 한 문장 정의

**Jazzytory 는, 클래식 체르니 100 정도의 손과 악보 읽기는 되지만 코드 심볼 앞에서 얼어붙는
학습자를, "리얼북 한 장만 놓고 세련되게 즉흥 연주하는 사람"으로 데려가는 웹 기반
재즈피아노 연주 전공 커리큘럼이다.**

---

## 2. 타깃 학습자 정의 (정밀화)

원 요청의 "체르니 100 수준"을 실행 가능한 진입 조건으로 번역한다.

**들어올 수 있는 사람 (Entry Persona — "지민")**
- 양손 독립이 초보적으로 되고, 한 손 5음 포지션을 넘어 이동할 수 있다
- 오선보를 느리게라도 읽는다 (초견 아님)
- 장음계 몇 개를 손가락 번호로 친다
- **모르는 것**: 코드 심볼(C‑7, F7♯11, B♭∆7), 텐션, 스윙 8분음표, 컴핑, "무엇을 칠지 스스로 정하는 것"
- **가장 큰 장벽**: 악보에 음표가 없으면 손이 멈춘다 (심리적 장벽 > 기술적 장벽)

**나갈 때의 사람 (Exit Persona)**
- 처음 보는 미디엄 스윙 스탠다드의 리드시트를 받고 **90초 안에** 조성·폼·주요 케이던스를 파악한다
- 왼손 루트리스 보이싱으로 컴핑하며 오른손으로 코러스 2개를 논리적으로 전개한다
- 블루스/리듬 체인지/AABA 스탠다드를 최소 30곡 암보로 연주한다
- 자기 연주를 녹음해 듣고 무엇이 문제인지 **스스로 진단**한다

> **핵심 설계 원칙**: 이 서비스의 성패는 "이론을 얼마나 가르쳤나"가 아니라
> **"음표 없는 악보 앞에서 손이 움직이기까지 걸리는 시간"** 을 얼마나 줄였는가로 측정한다.

## 3. 교육 설계 원칙 (Non‑negotiables)

1. **손 먼저, 이론은 뒤따라온다 (Hands‑first)**
   모든 개념은 *건반 위 실행 → 귀로 확인 → 이름 붙이기* 순서로 제시한다.
   개념 설명만 있고 그 자리에서 칠 것이 없는 모듈은 **반려 대상**이다.

2. **12키 원칙 (All Twelve Keys)**
   모든 핵심 드릴은 12키 순환을 전제로 설계한다. 한 키에서만 되는 것은 배운 것이 아니다.

3. **가이드 톤 우선 (Guide Tones First)**
   3음·7음을 통한 성부 진행이 모든 보이싱·즉흥의 뼈대다. 스케일 나열식 교육을 금지한다.

4. **곡 안에서 배운다 (Repertoire‑as‑Vehicle)**
   모든 개념 모듈은 최소 1개의 실제 스탠다드와 결합된다. 추상 연습만 있는 모듈은 미완성이다.

5. **귀 ↔ 손 ↔ 눈 삼각 결합**
   모든 모듈은 (a) 필청 트랙, (b) 건반 드릴, (c) 악보/분석 을 모두 갖는다. 하나라도 없으면 미완성.

6. **측정 가능한 통과 기준 (Jury Criteria)**
   각 레벨은 대학 실기 시험(jury)에 준하는 통과 조건을 갖는다. "이해했다"는 통과 기준이 아니다.
   "♩=120 에서 12키 ii‑V‑I 을 끊김 없이"가 통과 기준이다.

7. **모든 이론 주장에는 출처가 붙는다 (Sourced)**
   `SourceRef` 없이 서술된 이론 주장은 배포 금지.

## 4. 커리큘럼 골격 — 대학 4년제 연주 전공 매핑

| 레벨 | 제목 | 대학 대응 | 한 줄 약속 |
|---|---|---|---|
| **L0** | 진단과 준비 | 입학 오디션/배치고사 | 내 현재 위치와 갈 길을 안다 |
| **L1** | 코드 심볼의 문해력 | 1학년 1학기 (화성 I) | 코드 심볼을 보고 3초 안에 소리 낸다 |
| **L2** | 보이싱과 컴핑 | 1학년 2학기 (화성 II / 피아노 I) | 왼손이 자율적으로 반주한다 |
| **L3** | 코드 스케일과 선율 | 2학년 1학기 (화성 III / 즉흥 I) | 변화하는 화성 위를 걸어다닌다 |
| **L4** | 비밥 어휘와 채보 | 2학년 2학기 (즉흥 II / 이어트레이닝 III) | 남의 말을 외워서 내 문장에 쓴다 |
| **L5** | 리하모니제이션 | 3학년 1학기 (화성 IV / 편곡) | 같은 멜로디를 다르게 칠한다 |
| **L6** | 모달·컨템포러리 | 3학년 2학기 (현대 화성) | 2000년대 이후의 소리를 낸다 |
| **L7** | 솔로 피아노와 트리오 | 4학년 1학기 (앙상블/연주) | 혼자서도, 셋이서도 음악이 된다 |
| **L8** | 자기 언어 | 4학년 2학기 (졸업 연주) | 내 소리라고 부를 것이 생긴다 |

각 레벨은 3~6개 모듈, 각 모듈은 `개념 · 드릴 · 레퍼토리 · 필청 · 영상 · 평가 · 검수기록` 을 갖는다.

## 6. 검수(Editorial Review) 요구사항 — **정직성 규칙**

원 요청의 "버클리음대 등 유수의 교수 검수"는 다음과 같이 **실현 가능하고 정직한 형태**로 구현한다.

**반드시 지킬 것**
- 실존 인물(실명 교수)이 이 콘텐츠를 검수했다고 **주장하지 않는다.**
- 실존 인물의 이름·사진·서명을 검수자로 표기하지 **않는다.** (`Reviewer.isRealPerson` 은 항상 `false`)

**대신 구현할 것**
1. **검수 파이프라인 자체를 제품 기능으로 구현한다.**
   8항목 루브릭, 검수 상태 머신, 검수 의견 → 반영 기록, 모듈별 공개 배지.
2. **버클리 계열 표준에 정렬(align)한다.**
   각 레벨/모듈은 버클리 화성·이어트레이닝 과정 체계 및 **버클리 프레스 공식 교재**
   (Mulholland & Hojnacki, Santisi, Sifter 등)의 개념 순서에 매핑되며, 그 대응을
   `Level.berkleeAlignment` 와 `SourceRef` 에 명시한다.
3. **가상의 검수 패널을 명시적으로 가상이라고 밝히고 운영한다.**
   각 검수자는 "어떤 교수법 계보를 대표하는 심사 기준"으로 정의된다
   (예: 버클리 코드스케일 계열 / 배리 해리스 계열 / 채보 중심 계열).
   UI 와 문서 모두에 **"편집 검수 패널은 교수법 계보를 대표하는 가상의 심사 기준이며,
   실존 인물이 아닙니다"** 를 고지한다.
4. **외부 검수 슬롯을 비워 둔다.**
   `faculty-pending` 상태와 검수 요청 패키지 생성 기능을 제공해, 실제 교수 검수를
   붙이는 순간 배지가 `faculty-approved` 로 승격되도록 한다.

## 7. 저작권 규칙 (Hard Constraints)

- **멜로디를 배포하지 않는다.** 스탠다드는 **코드 진행(화성 골격)만** 수록한다
  (`Tune.melodyIncluded` 는 항상 `false`).
- 리얼북 스캔·PDF·가사·채보된 솔로 전체를 호스팅하지 않는다.
- 음원을 호스팅하지 않는다. 청음은 **앨범 메타데이터 + 청취 지시문**으로 제공한다.
- 유튜브는 **공식 임베드 플레이어**로만 사용하고, 다운로드·리호스팅하지 않는다.
- 오리지널 연습곡(컨트라팩트)은 Jazzytory 창작물로 표기한다.

## 8. 기술 제약

- **프론트엔드 전용**(백엔드 없음). 정적 배포 가능해야 한다. 진도는 `localStorage`.
- React 19 + TypeScript(strict) + Vite 8 + React Router 7. 런타임 UI 라이브러리 의존성 없음.
- 오디오는 **Web Audio API 합성**만 사용 (샘플 파일 배포 없음).
- 첫 화면 3초 내 인터랙션 가능, 모바일 400px 폭에서 깨지지 않음.
- 다크/라이트 테마 모두 지원, 키보드 접근성 확보.
- **깨진 유튜브 임베드를 배포하지 않는다** (미검증 ID 는 임베드 금지, 검색 폴백 사용).

## 9. 완료 정의 (Definition of Done)

1. `npm run typecheck` 무오류 (strict)
2. `npm run test` 전부 통과 (이론 엔진 단위 테스트 포함)
3. `npm run build` 성공
4. `npm run validate:content` 통과 — 모든 교차 참조 id 가 실존하고, 모든 모듈이
   개념·드릴·레퍼토리·필청·평가·검수기록을 빠짐없이 가짐
5. L1 첫 모듈부터 L8 마지막 모듈까지 **막힘 없이 클릭으로 도달** 가능
6. 배치고사 → 레벨 배정 → 모듈 학습 → 랩 연습 → 진도 기록의 **핵심 루프가 실제로 동작**

## 11. 이 문서를 읽는 에이전트에게

작업물을 제출하기 전에 스스로 물어라:

> **"체르니 100 수준의 지민이가, 이 화면을 보고, 30분 뒤에 건반 앞에서
> 무엇을 할 수 있게 되는가?"**

이 질문에 구체적인 동작으로 답할 수 없다면, 그 산출물은 아직 완성되지 않았다.
