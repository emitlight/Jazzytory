# 정보구조와 UX

담당: `ux-architect` · `design-system-engineer` · `a11y-i18n-engineer`

## 사이트맵

메뉴는 **네 개**다. 학습자가 고를 것이 많을수록 아무것도 고르지 않는다.

```
/                              홈 — 약속, 인터랙티브 데모, 원칙, 강좌, 정직성 고지
/placement                     배치고사 → 강좌 배정

── 강의실 (학습 동선) ─────────────────────────────────────────
/courses                       강의실 — 9개 강좌, 수강 상태, 학습 이어하기
/course/:levelId               강좌 홈 — 강의계획서 + 주차별 목차
/course/:levelId/lesson/:n     차시 — 그 단원의 모든 것이 순서대로

── 연습 랩 (도구) ────────────────────────────────────────────
/lab/voicing                   보이싱 랩 — 진행 × 보이싱 10종 × 12키
/lab/progression               진행 + 반주 + 기능 분석
/lab/keyboard                  코드 탐색기
/lab/ear                       청음 훈련
/lab/design                    연습 설계 — 매개변수를 하나만 고정
/lab/metronome                 메트로놈 (2·4박 기본)

── 자료실 (브라우징) ─────────────────────────────────────────
/library/tunes                 레퍼토리 목록
/library/listening             필청 명반 + 트랙 단위 청취 지시
/library/videos                영상 강의 + 추천 채널
/library/pedagogy              교수법 18가지
/library/glossary              용어집
/library/review                검수 정책 · 루브릭 · 패널 · 현황
/tunes/:tuneId                 곡 상세 — 코드 차트 + 반주 + 마디별 분석

/progress                      내 진도 — 8축 숙련도 · 오늘의 세션 · 복습 · 기록
```

구 경로(`/curriculum`, `/module/:id`, `/tunes`, `/listening`, `/videos`,
`/pedagogy`, `/glossary`, `/faculty`)는 모두 새 경로로 리다이렉트된다.

## 왜 LMS 구조인가

메뉴가 8개로 흩어져 있을 때, 한 단원을 학습하려면
커리큘럼 → 모듈 → 랩 → 레퍼토리 → 필청을 오가야 했다.
대학 LMS 의 어휘(강좌 · 강의계획서 · 주차 · 차시)를 그대로 쓰면 학습자가
이미 아는 동선이 되고, **차시 하나에 그 단원의 전부를 담으면 메뉴를 돌아다닐 일이 없다.**

| 도메인 | LMS 어휘 |
|---|---|
| 레벨 (L0~L8) | 강좌(course) |
| 모듈 | 차시(lesson) |
| 수료 기준 | 주리(jury) |
| 선수 모듈 | 선수 차시 |

### 차시 페이지의 순서

번호가 붙은 것은 장식이 아니라 **실제로 그 순서로 하라는 뜻**이다.

```
01 학습 목표      이 차시를 마치면 무엇을 할 수 있는가
02 개념           건반 예제가 본문 안에서 펼쳐진다
03 연습 방법      이 단원에 맞는 교수법
04 드릴           기록하면 숙련도가 올라간다
05 이 차시의 곡   레퍼토리
06 필청           트랙 단위 청취 지시
07 영상           외부 강의
08 통과 기준      실기 과제 · 자가 점검
09 검수 기록      루브릭 · 검수 의견
```

상단에 강좌 진도 바와 접히는 목차, 하단에 이전/다음 차시와 완료 체크가 붙는다.

## 핵심 루프

```
배치고사 ─▶ 오늘의 연습 ─▶ 모듈 학습 ─▶ 랩에서 손으로 확인 ─▶ 진도 기록 ─┐
              ▲                                                              │
              └──────────────────── 간격 반복 스케줄 ◀──────────────────────┘
```

이 루프를 흐리는 모든 것은 제거 대상이다.

## 설계 규칙

1. **3클릭 규칙** — 어느 화면에서든 3클릭 안에 "건반이 있는 화면"에 도달한다.
2. **다음 행동이 항상 하나** — 모든 페이지가 단일 CTA 로 끝난다.
3. **이론 텍스트 옆에는 항상 건반** — 개념 예제는 그 자리에서 건반으로 펼쳐진다.
4. **소리는 사용자 제스처 이후에만** — 페이지 진입만으로 소리가 나지 않는다.
5. **모바일 400px** — 건반은 가로 스크롤 컨테이너 안으로, 본문은 절대 가로 스크롤 없음.

## UX 라이팅

학습자를 가르치려 들지 않고 **옆에 같이 앉은 사람**처럼 쓴다.

**금지**: "간단합니다", "쉽게 배워보세요", "누구나"
→ 초심자에게 이 표현은 실패를 자기 탓으로 만든다.

**권장**: "여기서 대부분 막힙니다. 정상입니다. 이렇게 넘어갑니다."

버튼은 동사로. "확인" 대신 "이 보이싱 쳐보기".

실제 적용 예 (드릴 기록 화면):
> 정직하게 기록하세요. "틀린 데가 있었다"를 누르면 복습 간격이 줄어들 뿐, 벌점은 없습니다.

## 시각 언어

컨셉: **어두운 연습실, 빛나는 건반**.
재즈 클럽 클리셰(네온 사인, 색소폰 실루엣, 보라-핑크 그라디언트)를 쓰지 않는다.
참조점은 앨범 재킷이 아니라 음악 프로덕션 도구다. 악보와 건반이 주인공이고 UI 는 물러난다.

- **다크가 기본값**, 라이트는 완전히 지원되는 대안. 3상태 토글은 그대로 유지
- 강조색: 시그널 시안 — 다크 `#39d7f2`, 라이트 `#0a6575`
  보조(재생 중·케이던스 전용): 일렉트릭 아이리스 — 다크 `#a78bff`, 라이트 `#5b34d6`
- 화음 역할: 루트/3음/5음/7음/텐션/어보이드를 색 + **문자 라벨 + 모양 표식** 병기
  (색각 이상에서도 읽히게 — 색만으로 정보를 전달하지 않는다)
- 한국어 타이포: `line-height: 1.75`, `word-break: keep-all`
- 코드 심볼·템포·음이름은 모노스페이스 + `tabular-nums` — 계기판 숫자처럼

전체 토큰·클래스·접근성 체크리스트는 `docs/08-DESIGN-SYSTEM.md` 에 있다.

## 접근성

- 모든 인터랙티브 요소 키보드 도달 가능. 건반 키는 `aria-label`("시♭ 3옥타브")과 `aria-pressed`
- 라우트 전환 시 스크롤 최상단 + `<h1>` 포커스 이동
- 스킵 링크 제공
- `prefers-reduced-motion` 존중
- 오디오는 항상 정지 가능. 자동 재생 없음
- 다크/라이트/시스템 3상태 테마
