# 아키텍처

담당: `frontend-engineer` · `music-engine-engineer` · `audio-engineer`

## 원칙

**백엔드가 없다.** 이것이 가장 큰 설계 제약이자 선택이다.
학습 도구는 네트워크가 끊겨도 동작해야 하고, 서버가 없으면 서비스 종료로 학습 기록이
사라질 일도 없다. 진도는 `localStorage`, 내보내기/가져오기로 기기 이동을 지원한다.

## 계층

```
src/
├─ data/         콘텐츠 (순수 데이터, 로직 없음)
│   types.ts       ← 단일 타입 계약. 모든 데이터가 여기에 맞춘다
│   index.ts       ← 역인덱스 병합 + 조회 헬퍼
│   content.test.ts← 콘텐츠 정합성 게이트
├─ lib/          도메인 엔진 (React 를 모른다)
│   theory.ts      음 철자 · 코드 파서
│   scales.ts      코드 스케일 (기능 기반 판정)
│   analysis.ts    로마숫자 · ii-V 감지 · 조성 추정
│   voicing.ts     보이싱 생성 · 성부 진행 최소화
│   audio.ts       Web Audio 신스 · 룩어헤드 스케줄러
│   playalong.ts   워킹베이스 · 컴핑 · 드럼
│   mastery.ts     숙련 판정 · 간격 반복 · 세션 생성
│   storage.ts     localStorage 영속화
├─ components/   렌더링만. 도메인 로직 없음
└─ routes/       화면. 라우트 단위 코드 분할(lazy)
```

**규칙**: `lib/` 는 `components/` 를 import 하지 않는다. `components/` 는 계산하지 않는다.

## 핵심 설계 결정

### 1. 음을 피치클래스가 아니라 "문자 + 임시표 + 옥타브"로 표현한다
`B♭7` 의 3음은 `D` 이지 `C♯` 이 아니다. 피치클래스(0~11)만 쓰면 12키 이조에서
철자가 무너지고, 학습자에게 **틀린 음이름을 가르치게 된다.**
`degreeFrom(root, degree, alter)` 가 온음계 단계를 먼저 정하고 임시표를 역산한다.

### 2. 코드 스케일은 기능에서 따라 나온다
가장 흔한 교육적 오류가 "모든 도미넌트에 믹솔리디안"이다.
`chordScale(chord, ctx)` 는 명시된 얼터레이션 → 조성 내 기능 → 해결 방향 → 코드 성질
순서로 판정하고, **왜 그 스케일인지 문장으로 돌려준다**(`rationale`).

### 3. 오디오는 룩어헤드 스케줄링
`setTimeout` 으로 음을 재생하면 타이밍이 흔들려 연습 도구로서 무가치하다.
25ms 주기 타이머가 100ms 앞을 내다보며 `AudioContext.currentTime` 기준으로 예약한다.
`AudioContext` 는 **사용자 제스처 이후에만** 생성한다.

### 4. 컴핑은 의도적으로 쉰다
`COMP_PATTERNS` 에 빈 배열이 두 개 들어 있다. 실수가 아니다.
쉬지 않는 반주는 학습자의 연주를 덮고, 자기 소리를 못 듣게 만든다.

### 5. 교차 참조는 양방향 병합
커리큘럼 작성자는 "이 모듈에 이 앨범"이라 쓰고, 청음 큐레이터는 "이 앨범은 이 모듈에"라 쓴다.
`data/index.ts` 가 역인덱스를 만들어 합집합으로 병합한다. 어느 쪽에서 써도 연결이 산다.

### 6. 깨진 유튜브 임베드를 배포하지 않는다
`verified === true` 이고 `videoId` 가 있는 항목만 iframe 이 된다.
그 전에 썸네일(`i.ytimg.com`)로 실제 생존을 한 번 더 확인하고, 실패하면 검색 폴백으로 전환한다.
`npm run verify:media -- --write` 가 oEmbed 로 확인해 플래그를 갱신한다.

### 7. HashRouter
정적 호스팅(GitHub Pages 등)에서 서버 리라이트 없이 딥링크가 동작해야 한다.

## 번들 크기 — 알려진 한계

현재 프로덕션 번들 (gzip 기준):

| 청크 | 크기 | 언제 받는가 |
|---|---|---|
| `index` (앱 셸) | ~5 KB | 즉시 |
| `index.css` | ~4 KB | 즉시 |
| `vendor` (React·라우터) | ~82 KB | 즉시 |
| `content` (커리큘럼 전체) | **~327 KB** | 첫 라우트 진입 시 |
| 라우트별 청크 | 각 1~12 KB | 해당 화면 진입 시 |

`content` 가 무겁다. 51개 모듈의 본문(134개 개념, 323개 예제)과 29곡·38앨범·99용어가
전부 들어 있기 때문이다.

**레벨별로 쪼개는 시도는 효과가 없었다.** `data/index.ts` 가 모든 모듈 파일을
정적 import 하므로 모든 청크의 로드 조건이 같고, 번들러가 다시 하나로 합친다.
진짜로 나누려면 콘텐츠 접근을 동적 import 로 바꿔야 하고, 그러면 `MODULES` 를 쓰는
모든 라우트가 비동기가 된다. v1 에서는 그 복잡도를 지지 않기로 했다 —
로드맵의 v1.1 항목으로 남겨 두었다.

앱 셸 자체는 91 KB(gz)로 즉시 상호작용 가능하고, 콘텐츠는 그 뒤에 도착한다.

## 품질 게이트

```
npm run typecheck        strict, 오류 0
npm run test             이론 엔진 + 콘텐츠 정합성
npm run validate:content 콘텐츠 정합성만
npm run build            타입체크 + 번들
```

`content.test.ts` 가 강제하는 것: 존재하지 않는 id 참조, 중복 id, 순환 선수 그래프,
폼과 마디 수 불일치, 파싱 불가 코드 심볼, 출처 없는 개념, 측정 불가능한 통과 기준,
저작권 규칙 위반(`melodyIncluded`), 정직성 규칙 위반(`isRealPerson`, 대학 소속 표기),
미검증 영상의 videoId 존재.
