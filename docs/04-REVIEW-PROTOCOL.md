# 검수 프로토콜 (Editorial Review Protocol)

담당: `faculty-reviewer` · 최종 갱신 2026-09

## 0. 정직성 선언 — 가장 중요한 절

원 요청은 "버클리음대 등 유수의 재즈피아노 연주 전공 교수들의 검수"를 포함했다.
Jazzytory 는 이를 다음과 같이 **실현 가능하고 정직한 형태**로 구현했다.

### 하지 않은 것
- 실존 교수가 이 콘텐츠를 검수했다고 주장하지 **않는다**
- 실존 인물의 이름·사진·서명을 검수자로 표기하지 **않는다**
- 실제 대학의 승인·인증·제휴를 시사하지 **않는다**

### 한 것
1. **검수 파이프라인 자체를 제품 기능으로 구현했다.**
   8항목 루브릭, 상태 머신, 검수 의견 → 반영 기록, 모듈별 공개 배지, 집계 대시보드.
2. **실존 공개 교재의 개념 체계에 정렬했다.**
   각 레벨은 버클리 화성·이어트레이닝 과정 계열에, 각 개념은 버클리 프레스를 비롯한
   실존 교재의 개념에 매핑되고 `SourceRef` 로 명시된다.
   *정렬(alignment)은 승인(endorsement)이 아니다.*
3. **검수 패널을 명시적으로 가상이라고 밝히고 운영한다.**
   6개 검수 기준은 인물이 아니라 **교수법 계보의 인격화**다.
   `Reviewer.isRealPerson` 은 항상 `false` 이며, 테스트가 이를 강제한다.
4. **외부 검수 슬롯을 비워 두었다.**
   `faculty-pending` 상태가 준비되어 있고, 실제 교수 검수가 붙는 순간
   `faculty-approved` 로 승격된다.

> 자동 테스트(`src/data/content.test.ts`)가 이 규칙들을 빌드 게이트에서 강제한다.
> 실존 인물 표기나 대학 소속 표기가 들어오면 빌드가 실패한다.

## 1. 검수 패널 — 6개 심사 기준

| id | 대표 계보 | 무엇을 반려하는가 |
|---|---|---|
| `rv-chord-scale` | 버클리 코드스케일·기능화성 | 기능 고려 없이 기계적으로 붙인 코드 스케일 |
| `rv-barry-harris` | 배리 해리스·밥 구전 | 이론은 맞지만 밥 어법에서 나오지 않는 라인 |
| `rv-transcription` | 채보 중심·귀 우선 | 귀로 확인하지 않고 종이에서만 성립하는 서술 |
| `rv-contemporary` | 컨템포러리 보이싱·포스트밥 | 현대 어법을 1960년대 문법으로 설명하는 것 |
| `rv-keyboard-technique` | 클래식 전향자 테크닉·손 건강 | 이 단계의 손으로 불가능한 확장·운지 |
| `rv-pedagogy` | 음악교수법·학습설계 | 측정 불가능한 목표, 인지 부하 초과, 선수학습 누락 |

## 2. 8항목 루브릭

각 1~5점.

| 항목 | 묻는 것 | 5점의 모습 | 3점 이하의 모습 |
|---|---|---|---|
| accuracy | 이론적으로 틀린 서술이 없는가 | 전부 검증 가능 | 사실 오류 존재 |
| terminology | 표기·용어가 통용 표준인가 | 전 프로젝트 일관 | 자의적 번역어 |
| sequencing | 선수학습 없이 등장하는 개념이 없는가 | 의존 그래프 무결 | 앞선 개념 선행 등장 |
| playability | 이 난이도의 손으로 가능한가 | 음역·운지 검증됨 | 초급에 10도 확장 |
| idiom | 재즈 관용어법으로 자연스러운가 | 실제 연주에서 들림 | 이론적으로만 맞음 |
| integration | 청음·레퍼토리·드릴이 연결되는가 | 셋 다 있음 | 추상 연습만 |
| assessability | 통과 기준이 관측 가능한가 | 템포·키 명시 | "이해한다" |
| sourcing | 주장에 출처가 붙어 있는가 | 전 개념 인용 | 근거 없음 |

**반려 조건**: 평균 4.0 미만, 또는 accuracy / playability 가 3 이하.

## 3. 상태 머신

```
draft ──내부 이론 검수──▶ internal-reviewed ──외부 요청──▶ faculty-pending
                                │                              │
                                │                     ┌────────┴────────┐
                                ▼                     ▼                 ▼
                        revision-required ◀──── (반려)          faculty-approved
                                │
                                └──수정 후 재검수──▶ internal-reviewed
```

현재 상태: 전 콘텐츠가 `internal-reviewed` 또는 `faculty-pending`.
**`faculty-approved` 는 0건이다** — 실제 외부 검수를 받지 않았으므로.

## 4. 검수 의견 작성 규칙

`ReviewComment` 는 **지적(issue) + 실제 반영(resolution)** 쌍으로만 쓴다.
반영하지 않을 거면 코멘트를 달지 않는다. 장식용 검수 기록을 만들지 않는다.

심각도
- `blocker` — 사실 오류·저작권 위반. 배포 불가
- `major` — 계열성·연주 실현성 문제. 수정 필요
- `minor` — 표기·용어 문제
- `suggestion` — 개선 제안

## 5. 실제 외부 검수를 붙이려면

1. 대상 모듈의 `review.status` 를 `faculty-pending` 으로 둔다
2. 검수자를 `src/data/faculty.ts` 에 추가한다
   — 이때 `isRealPerson` 은 타입상 `false` 로 고정되어 있다.
   실존 인물을 추가하려면 **먼저 본인 동의를 받고** 타입을 확장해야 한다.
   이 마찰은 의도된 것이다.
3. 8항목 루브릭을 채우고 `reviewedAt` 을 기록한다
4. 통과 시 `faculty-approved` 로 승격 — UI 배지가 자동으로 바뀐다
